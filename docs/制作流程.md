# 《anything2explainer》双版科普视频 · 制作流程

> 本文从本仓库第一部双版影片《PCAP — Packet Capture, Explained》（横版 YouTube 5′17″ / 竖版 TikTok 69″，v3）的实际生产过程凝练而来，是一份可复用的生产 SOP。
> 上游方法论与可编译模板来自 [anything2explainer](https://github.com/Vincentwei1021/anything2explainer)（Remotion 4 + React 19 + TypeScript，逐帧代码绘制）；本文只讲"怎么把一个主题做成两部片子"的实操顺序、判据与坑。

---

## 1. 成品形态与总体思路

| | 横版 | 竖版 |
|---|---|---|
| 目标平台 | YouTube（16:9，1280×720） | TikTok（9:16，720×1280） |
| 风格定位 | 详细、严谨、章节化叙事 | 快节奏、单线、钩子前置 |
| 典型时长 | 3–5 分钟，3–4 章 | 60–75 秒，单章 |
| 镜头规模 | 40±，8 个构建组 | 12–14，3 个构建组 |

**双版共享一条故事主线、一套视觉母题、一个贯穿示例**（PCAP 片：信封=包、`The wire doesn't lie.`；9 秒结账页之谜作为唯一案例）。竖版不是横版的裁切，而是**同一主线的重新分镜**：横版按章节推进论证，竖版按"钩子 → 三步揭示 → 反转 → 收束"压缩。

全片视觉语言固定：黑底幕底（点阵波）、白色 2–3px 线条图形、紫色 = 当前重点 / 橙色 = 数字与警告 / 灰色 = 非活跃 / 绿色 = 正确，44px 白字黑边字幕，底部章节进度条，顶部胶囊 HUD。**画面全部代码绘制**；如引入真实照片/实拍素材，只用可核来源（如 Wikimedia Commons）并登记 `MANIFEST.md`（来源 URL / 许可 / sha256 / 用途镜头）。

## 2. 环境与前置

- Node ≥ 20（npm install 后磁盘 ≈650MB/片）、Python 3（`edge-tts`、Pillow、numpy）、ffmpeg；渲染机 2 核也能跑，只是把并发调低。
- 无 zsh 时所有 `.sh` 脚本用 `bash` 执行。
- 帧号 **1 起含端点**：`TOTAL_FRAMES` 来自 `src/common/timeline.ts`（`tts_build.py` 生成）；镜头区间 `[from, to]` 首尾相接。
- 工具脚本（每片 `scripts/`）：

| 脚本 | 作用 |
|---|---|
| `tts_build.py` | 解说词 → 配音 wav + `timeline.ts` + `subs.ts` + `timeline.md`（逐句缓存，改一句只重合成一句） |
| `render_storyboard.py` | `script/storyboard_src.md`（令牌格式）→ `分镜表.md`（带真实帧号） |
| `still.sh <Comp> <帧列表> <目录> <tag>` | 帧级精确出图（bundle 缓存 `build_dev_<tag>`，改码后要 `rm -rf` 重建） |
| `test_render.sh <Comp> <起始帧> <tag>` | 30 帧测渲（验证镜头能渲、大致 fps） |
| `preview.sh 30` | 前 30 秒样片（风格定版用） |
| `render.sh` / `render_chunk.sh` | 整片渲染 / 分块渲染 + ffmpeg concat |
| `selfcheck.py` | 静态自检：帧覆盖对账、闪烁白名单计数、扫光白名单计数、画面字面量 vs 事实清单 |
| `tools/humanize.py`（仓库级） | 解说词/标题/简介 → humanizer 改写 + 事实存活 audit，见阶段 2 |
| `frame_metrics.py` | 逐镜头量最大物体高度 / 主角区柔光 / 碎屑 / 空场 |
| `motion_check.py` | 节奏体检：最长静止 ≤3 s、末拍稳定期 ≥30 帧（组级低分辩率偏松，**成片 `--frames fin_frames` 复测才是判据**） |
| `sheet.py` | contact sheet 拼图 |

## 3. 阶段 0 · 建项目（脚手架）

```bash
bash <template>/scripts/new_project.sh <工作目录> <slug>   # 复制模板 + npm install + tsc
```

- `slug` 决定素材目录 `public/assets/<slug>/`（配音、照片都放这里）。
- 英文片立刻改 `src/config.ts`：`lang:'en'`、`title.rest=''`。
- **从第二部片子起**，更稳的做法是复制**上一部已交付工程**（继承全部模板修复：HUD 换词过渡、进度条真实章界、竖版 ProgressBar 等），只替换 `script/ research/ 分镜表.md src/shots/ ui.tsx 的本片图元段`。跨片 `node_modules` 相同的可直接软链，省 650MB × N。

## 4. 阶段 1 · 调研（事实层，先于一切文案）

- 派研究员或用 web 搜索批量核实，产出 `research/<主题>-research.md`：每个数字/年份/人名/RFC 号带来源 URL；**调研没核实的不上画面、不进解说词**。
- 需要核实的类型：起源（论文、RFC、年份、人物）、机制（握手、头部格式、重传、拥塞控制）、边界与对比、现代演进（QUIC/HTTP3）、易错点（"流媒体用 UDP"这类常见误解要专门核实）。
- 产出必须含：**数字与比喻清单**（每条标可信度与日常尺度换算）、术语表、待核清单。
- 示例数据（页面耗时、IP 地址用 TEST-NET 段等）标"示意"，交付说明里注明。

## 5. 阶段 2 · 解说词与时间轴

**格式**（`script/narration.txt`，tts_build.py 的输入）：

```
# CHAPTER n 章标题          ← 章节标记（章前自动加空白）
一句话|按竖线切成字幕短句    ← 竖线只切字幕，不影响朗读
                            ← 空行 = 段落分隔：段末句停顿 PARA_GAP，段内小句只留 GAP
## gap 20                   ← 手动加停顿（给末拍元素落位停留用）
```

**写作原则**（决定片子好坏的一层，比格式重要）：
- 处境开场（一个具体到能画出来的现象），一条主线贯穿到底，先因后果；
- 数字换算成可感尺度；比喻承重且讲清失真处；
- 章界有起承转合：章末留钩子、章首回指上一章成果再开题；
- 结尾回扣开头之谜；术语先现象后名词；不描述画面（画面自己会说）。
- 英文块 ≤48 字符/字幕块；直引号不用弯引号；省略号用 `...`。

**人味打磨（必做，每部片）**：初稿写完后整篇过一遍 [humanizer](https://github.com/blader/humanizer)（基于 Wikipedia《Signs of AI writing》的 26 条 AI 腔改写规则，仓库内置于 `tools/humanizer/`）：

```bash
python3 tools/humanize.py script/narration_draft.txt script/narration_humanized.txt --genre narration
```

- 脚本把 humanizer 的 `SKILL.md` 作为系统提示词驱动 LLM 改写，只动语感不动事实：去掉 "not just X but Y"、假排比、堆叠破折号、"Let's dive in"、空泛收尾句这类 AI 腔，保留全部事实与术语。
- 产物旁自动生成 `.audit.md`（草稿里的数字与专名逐个在改写稿里找，缺失即 MISSING）：**事实必须原样存活**，audit 报 MISSING 就人工修，不允许"顺手"改数字。
- 双版解说词、封面文案、平台标题与简介（`--genre title` / `--genre description`）同样要过这一步——平台标题最容易被 AI 腔毁掉点击欲。

**配音**：英文用 `edge-tts`（有词级边界，字幕节拍最准）：

```bash
TTS_ENGINE=edge VOICE=en-US-AndrewNeural RATE=+0% python3 scripts/tts_build.py
```

- 跑完核对：成片时长落在目标区间（差 >15% 改句子重跑，别改语速）；它列出的**末块 <45 帧的段末句**要加 `## gap 15–30`。
- **定稿后不再改词**——帧号会被每个镜头硬编码，改一个字全片重对位。

## 6. 阶段 3 · 分镜

写 `script/storyboard_src.md`（令牌 `{S12.from-8}` `{S12.c3}` `{C2}` 引用时间轴真实帧号）→ `python3 scripts/render_storyboard.py` → `分镜表.md`。

- **镜头按画面单元分，不按句分**：短句（<3 s 或单块）并入相邻镜头当节拍；单镜头 ≥120 帧；能承接（同一元素带到下一镜）就不清场。
- 每镜头一行：帧区间 / 节拍 / 画面 / 动效（含运镜）/ **主角·尺寸** / **光**；每镜头必须有「持续：…」（这个字幕块的动词靠哪个持续动作撑到下一拍）和「停留：…」（末拍元素落位后 ≥30 帧再离场）。
- 分镜表末尾的**全局约束**是全片的法律：贯穿示例、闪烁白名单（每镜头 ≤1 处，只给核心术语）、扫光白名单（三轮紫光横扫全片 ≤2 镜头）、事实清单、高光时刻清单（每章 ≤1 个，标类型）、运镜清单（每章 ≥3 处）。
- 坐标写下去前用 `textW()` 估一次字宽（英文一行比中文宽得多），能省一半构建组的裁定请求。
- **末镜头要单独算一张表**：末字幕块起始帧 / `endingFade` 压黑起始帧 / 中间有没有白闪——`(末句 to − endingFade) − 末字幕块起始帧 ≥ 30 帧`，否则结论读不完（用 GlitchIn 收尾要按双倍预算算，12 帧里一半是灭的）。

## 7. 阶段 4 · 覆盖层、图元与探针

- `src/config.ts`：`slug/lang/bg/title{big,en,tagline}/chapterTech/hud(导航标签，名词短语)/rails(可选流程轨)/endingFade(6–15)`。**片尾署名 `builtBy` 按需设 `''`**（本项目按用户要求去掉默认署名画面）。
- `src/ui.tsx` 按主题补 2–12 个语义图元（网络类可复用：`PacketIcon` 信封、`BrowserMock`、`LogCard`、`SwitchBox`、`ClockIcon`…），**跨组共用的常量（贯穿示例、布局坐标、缓动小工具）必须放进共用层**，不让构建组互相对齐。
- **派构建组之前先跑探针**：临时合成（如 `probe.tsx` 的 `Icons`）一帧渲染所有新图元，VLM 看一眼——像素分区、文字是否压线、光效是否糊。10 分钟成本，避免 8 个组集体做错。
- 真实照片素材此时落位：`public/assets/<slug>/` + `MANIFEST.md` 登记 + 专用图元（如 `PhotoCard`：白框 + 暗调 grade 融入黑底 + 灰色出处小字）。出处小字要在所属镜头内 ≥2.5 s（≥75 帧）的 ≥50% α 停留。

## 8. 阶段 5 · 并行构建（波次派单）

- 横版 8 组 / 竖版 3 组，每组 5–7 镜头，**每组一个 agent，4 个一波**，完成即释放再派下一波（pane/fork 有全机共享上限）。
- 每组派单带：`BUILD_RULES_<片名>.md`（本片补充规则：必读文件顺序、专用图元 API、英文排版硬规则、白名单摘要、still/VLM 自检命令、交付物格式）+ 分镜表该组切片 + 时间轴该组句子。
- 构建组协议要点：只改 `src/shots/<Gn>/**`；`const N = useCurrentFrame() + F0`；纯函数、随机只用 `rnd`；入场以镜头首帧为 f0（别等节拍帧）；硬切前离场归零 `1−(n/N)^1.5`；入场轨迹不穿字幕带（自下 Δ≤120）；每镜头 ≤600 DOM；禁 `feConvolveMatrix`、σ≥1 的 blur。
- 收组后主会话跑 `selfcheck.py`（几秒，抓 QC 从像素查不到的：帧空洞、白名单超标、事实清单外字面量）。
- 构建组的合理偏离（换示例文本、改拓扑、缩帧数）有出处就放行，一句话裁定并记 `BUILD_NOTES`。

## 9. 阶段 6 · 渲染

```bash
npx tsc --noEmit          # 零错误才渲
VER=v1 bash scripts/render.sh
```

- 单次渲染会超工具超时（10 分钟）的机器用 `render_chunk.sh` 分块渲 + `ffmpeg -c copy` concat；分块边界用像素 diff 验证（正常 0.05–0.6，接缝级 ≈0）。
- 成片帧序列 `fin_frames/` 留给 motion_check 成片复测与 QC。

## 10. 阶段 7 · QC 与修复

1. 主会话先跑 `frame_metrics.py`（空场/主角无光/碎屑标记先于派修）+ `motion_check.py --frames fin_frames`（成片复测才是判据；组级读数偏松，v1 组级全过、成片复测 11 镜超限是真实发生过的）。
2. VLM 抽帧审：每镜头中点 + 入场帧，章节卡、片尾必查；VLM 标记逐条用全分辨率 still 复核（缩略图伪影很多）。
3. 按组派修复 agent（一个只修一到两组），覆盖层问题主会话自己修。
4. 渲 v2 → 复验（逐条核 v1 问题 + 回归通读）→ 小修 → v3。
5. **进度条像素校验**（用户报告过的真问题）：渲成片后抽 8 个采样点，量进度条填充边缘 x 坐标 vs 期望值，偏差应 <2px；竖版进度条要确认条体可见（高度从 `H` 推导，不是写死横版值）。
6. 终检清单：闪烁白名单核对（源码级计数）、扫光出现镜头数 = 白名单条数、高光时刻/运镜清单逐条看帧、组界帧、片尾逐帧对齐 ground-truth。

## 11. 阶段 8 · 交付

- 成品入 `download/`，命名 `<主题>_Explained_<平台>_<尺寸>.mp4`。
- 写 `交付说明.md`（成片规格、配音来源、事实出处、示例语境、质检结论、已知保留项）。
- GitHub：干净工作树（排除 `node_modules/ build*/ renders/ stills/ qc/ audio/cache/ .env`）→ push → 建 Release，资产 = 双版 mp4 + 双版配音 wav + 双版封面 png（上传接口偶发 404，用重试循环）。

## 11.5 阶段 8.5 · 封面与平台标题（每部片必做）

从第三部片子（APK）起，每部片交付时同步产出三样发布物料，缺一不算交付完成：

1. **视频封面**（每版一张，代码绘制，与片子同一套视觉语言）
   - 工程里加一个 `Cover` 合成（单独注册，不进正片时间轴）：横版 1280×720（YouTube 缩略图规格），竖版 720×1280（TikTok 封面）。
   - 封面不是镜头截图：大字钩子（全片最反直觉的一句话，Noto900 ≥90px）+ 一个视觉母题图形 + 黑底高对比——信息流里缩到 200px 宽仍要能读。
   - 渲染：`npx remotion still src/index.ts Cover out/cover.png`；命名 `<FILM>_Cover_<平台>_<尺寸>.png`。
   - 自检：缩到 200px 宽截图看一眼可读性；标题文字不压安全区（TikTok 右侧按钮列 / 底部 UI）。
2. **平台标题**（`script/publish.md`，随工程提交，也进交付说明）
   - YouTube：1 个主标题（≤70 字符、具体带钩子、不用"惊呆了"式夸饰）+ 视频简介（含事实出处链接）+ 标签。
   - TikTok：标题句 + 3–6 个 hashtag（含 #android #programming 类目标词）。
   - 标题与简介同样过 `tools/humanize.py`（`--genre title` / `--genre description`），标题里的 AI 腔最劝退。
3. **对账**：交付清单里封面与标题各占一行，Release 资产里封面必须可见。

## 12. 竖版改造清单（从横版模板到 9:16）

1. 画布与合成：`common/lib.tsx` 的 `W/H` → 720×1280；`Root.tsx` 组数裁到 3 组。
2. 安全区换挡：内容主区 **y240–990、x40–620**（右侧 x>620 留给 TikTok 按钮列，顶部 y<240 留给平台 UI）；中轴 x=360；字幕带 **y1002–1056**；进度条 **y1240–1280**。
3. `Subtitle.tsx` 竖版化（位置 y1002）；`ProgressBar.tsx` 条高从 `H` 推导（**不要留横版 720 的硬编码**——曾导致整条不可见）；HUD 胶囊、Glitch 参数、扫光 bars 位置全部按竖版坐标重写。
4. `fx.tsx` 的 `CameraRig` 去硬编码 1280×720（或提供竖版 `CamRigV`），运镜幅度按竖版视野放大。
5. 字号：手机观看最小 22px 尽量 24+，大字可到 130px；自下滑入 Δ≤100、侧向 Δ≤180。
6. 分镜策略：单章 12–14 镜，每镜 150–200 帧，高光时刻前置（钩子在前 3 秒）。

## 13. 坑速查（每条都真实返工过）

| 坑 | 修法 |
|---|---|
| `fadeIn(0)` 返回 0，首帧空屏 | 用 `softOp(n+1, 6)`（首帧 ≈57%） |
| kf 首值陷阱：t<首关键帧返回首值 | 入场表以 `[镜头起始帧, 画外值]` 开头 |
| 硬切前离场末帧还剩 40%+ | 归零用 `1−(n/N)^1.5` |
| 片尾压黑吃掉末镜头收尾/结论大字 | `(末句 to − endingFade) − 末字幕块起始帧 ≥ 30`；GlitchIn 按双倍预算 |
| 进度条分隔线等宽 25/50/75 与真实章界不符 | 分隔线按章节卡实际出现帧计算 |
| 竖版进度条不可见 | 条高从 `H` 推导，像素校验 |
| 计数动画中间值是"没出处的事实" | 中间值不可读（重 blur）或不做计数 |
| `scale` 把字号带破 22px 下限 | 缩放处所有字号 × 系数对账 |
| 拉丁字母 scaleX 压窄 / 弯引号全宽 | `SQUEEZE`（en=1）；直引号 |
| 一行英文超宽溢出 | `textW()` 估宽，别目测 |
| 组级 motion_check 过 ≠ 成片过 | 成片 `--frames fin_frames` 复测 |
| agent 跑一小时零产出 | "边查边 append"写进派单，是硬要求 |
| 出 still 后改码不生效 | `rm -rf build_dev_<tag>`（bundle 缓存） |
